## Calculator Semantics (v7 notes)

- **Evaluation order**: every argument of a call is evaluated left to right first; the function's own checks (array/scalar kind, `rows`/`cols`, length, coordinates) run afterwards. An evaluation error in any argument (for example `1/0`) is therefore reported before a shape or range error of the same call.
- **Decimal arithmetic**: calculations use `System.Decimal` with C# rules (28-29 significant digits; a result that needs more digits is rounded to the nearest representable value and an exact tie goes to the even last digit; no intermediate rounding by the calculator). `System.Decimal` is not IEEE 754 decimal128. Only the optional `decimalPlaces` output rounding (`MidpointRounding.AwayFromZero`) is applied to results. Example: `1/3*3` is `0.9999999999999999999999999999`, not `1`.
- **Zero**: a zero result is always `0` (negative zero and trailing zeros of a zero are dropped); the JSON response prints `0`, and trailing zeros of non-zero values are stripped there as well, so the scale of a decimal is not preserved.
- **`arr_scan(expr, accVar, itemVar, arr, init)`**: `out[i] = expr(acc = out[i-1], item = arr[i])` with `out[-1] = init`; `init` is not part of the result, so `len(out) == len(arr)`. Example: `arr_scan(acc + x, acc, x, [1, 2, 3], 0)` returns `[1, 3, 6]`. With an empty `arr`, `init` is still evaluated and `expr` runs zero times.
- **Size limits**: an array holds at most 512 elements, so a matrix has `rows*cols <= 512`. `mat_hstack` takes 2 to 16 columns and `n*k <= 512`, i.e. at most `floor(512/k)` rows for `k` columns (4 columns: 128 rows; 16 columns: 32 rows); a daily series of 252 bars fits at most 2 columns. `det3` takes 9 arguments.
- **Time axis and causality**: arrays carry no dates and all elements are visible at once; the calculator does not check whether a value uses information from later positions. These functions can use later elements:
  - depends on the arguments: `arr_shift(a, k, fill)` with `k < 0` (a lead: `out[i] = a[i - k]`), and `convolve(a, b, 1)` (the centred `same` slice uses elements on both sides of a position);
  - always arbitrary position or whole-array order: `arr_take`, `arr_reverse`, `arr_sort`, `arr_rank`, `arr_unique`, `arr_get`, `arr_slice` and `a[i]`;
  - whole-array aggregates (`sum`, `avg`, `zscore`, `quantile`, ...) use every element.
  `arr_shift` with `k >= 0`, `diff_lag` (lag `k >= 1`), `arr_scan` and element-wise functions only look backwards. If the calculator is later connected to backtests, the screener or custom indicators, the causality guard must be designed again on the execution-context side.

## Common Errors

- `INVALID_ARGUMENT`: Missing required argument, wrong type/shape, invalid date range, or mutually exclusive arguments.
- `LIMIT_EXCEEDED`: Requested count, window, symbol list, or estimated response tokens exceeded server bounds.
